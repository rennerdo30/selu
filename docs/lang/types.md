# Named types

Module-level `type Name = T;` and `interface Name { field: T; optional?: U; method(a: A): R; }` declare types in a separate namespace. They are visible throughout the module, including before their declaration. Type names may be Lua keywords because they never become Lua identifiers. The compiler prefix `__selu` is reserved, including on type parameters.

Both forms accept generic parameters and `extends` constraints. Generic function inference and default type arguments are not yet supported. For example, `type Pair<T extends number> = [T, T];`. Interfaces can extend object-shaped named types; their inherited fields are merged, and conflicting overrides are errors. Methods describe function-valued object fields and use ordinary dot calls. Class compatibility retains the data-only structural rule in classes.md.

Aliases work in nested written types, tuple returns, array initializers, callback contexts and rest parameters. Diagnostics retain the written outer type name. Underlying shapes are inspected through one cycle-safe helper in aliases.rs. Recursive object/interface and generic types use shared definition cells with weak recursive references. Instantiation and comparison keys use declaration identity (module and declaration offset) plus structural identities of actual type arguments; display names are separate. Completed instantiations and declaration diagnostics are cached. The expression type table retains definition roots; comparison tracks recursive pairs. Alias chains may recurse through objects or containers, in either declaration order. Bare and optional-only alias cycles are rejected, and expanding generic recursion is bounded at 64 active instantiations with SELU0523.

`export type` and `export interface` use ordinary named imports, including aliases. Export metadata carries their private supporting definitions. Import resolution qualifies these supporting names by defining module so they cannot leak into the importing module's type namespace or collide with its own names. Type-only imports have no value binding. A type and a value may share one exported name, and an ordinary named import brings both namespaces into scope. An imported type and a local declaration of the same type name conflict. Private class references retain the defining module's resolution context. Type declarations, exports and imports generate no Lua namespace entries or source locals. A module containing only type declarations and type-only imports emits only its loader line; standalone lowering emits no statements.

`unknown` is an explicit opt-in boundary. Every value fits unknown, but unknown does not fit a specific declared type. It may be stored, passed to an unknown parameter, returned as unknown, or compared for equality. Arithmetic, member/index access, calls and conditions require appropriate narrowing. Untyped game values remain the existing internal untyped type.

Selu's `typeof` returns Lua type names: `"nil"`, `"number"`, `"string"`, `"boolean"`, `"table"` and `"function"`. It never returns `"object"` or `"undefined"`. This intentionally differs from TypeScript, where `typeof null` is `"object"`.

`typeof x == "table"` narrows `X?` to the existing `X`, retaining its fields; a known function keeps its signature. When the original value is unknown, these checks establish only a table or an unknown-returning callable. Primitive guards narrow unknown to the checked primitive. `typeof x == "nil"` narrows to null, while `!= "nil"` gives the non-null type. Negation, short-circuit and early-return handling propagates the corresponding facts. `if (x)`, `!x`, `&&` and `||` reject unknown and suggest an explicit guard. A null check alone cannot establish a primitive or object shape for unknown. Optionality is idempotent through named shapes, and null checks remove all optional wrappers.

`typeof` lowers to a call through one protected capture of Lua `type`, emitted only in files that use it. A source binding named type cannot change the intrinsic. Type declarations have no runtime allocation or idle cost.

Diagnostics SELU0520-0525 cover duplicates, placement, argument count, cycles, constraints and inheritance. SELU0527 covers duplicate interface fields. Existing value/type mismatch diagnostics remain in force and print named types where available.

The named-types example prints `Quest` and `7` on PLAYER_LOGIN. Its expected output was calculated from score(7) and the single array insertion; expected.lua records the generated Lua.

Interface method signatures retain final rest parameters. Rest parameters before another parameter and defaults in signatures are rejected. Declaration diagnostics point at duplicate parameter/member names and are emitted once per declaration. Resolved alias bodies are validated recursively, including unused declarations; aliases cannot conceal nullable array elements or nonserializable saved data.
